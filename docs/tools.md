# Tool reference

## Start with the standard profile

The default Android/Shield server lists **10 tools** (9 on Apple TV) for connection checks, Kodi status, add-ons,
settings and logs. Enabling writes adds four everyday controls, plus (on Android) the file-backup list, read and restore tools needed to undo setting changes. A configured Manager token adds
three inspection/preview tools, plus five more when writes are enabled. Provider directory browsing
is listed only with its separate `NVIDIA_MCP_ALLOW_PLUGIN_BROWSE=1` opt-in.

For file repair, screenshots, Android logs, app inventory or APK upgrades, set
`NVIDIA_MCP_TOOL_PROFILE=full` in the MCP client's private server environment, then restart/reload
that server. The full Android catalogue has 23 tools without write permission and 35 with writes; provider
browsing adds one more when opted in. Unsupported Android tools are omitted on Apple TV; see its
[capability table](apple-tv.md#what-matches-the-shield-workflow).

Profiles control discovery, **not permissions**. Unlisted tools and old names remain callable for
existing workflows, with the same platform, write, viewing, checksum and trust guards. Write tools
are not registered at all without `NVIDIA_MCP_ALLOW_WRITES=1`. No profile enables deletion, add-on
removal, arbitrary shell/RPC or automatic device discovery.

## Choose the right operation

- **Settings:** list core values with `kodi_list_settings`, then use `kodi_set_setting`.
  - For one add-on, use `kodi_list_addon_settings` and `kodi_set_addon_setting` instead.
- **Text-file repair:** read with `kodi_read_file`, review `kodi_preview_file_patch`, then apply
  the same edits with `kodi_apply_file_patch` while Kodi is stopped.
  - `kodi_create_file_backup` creates one local snapshot; `kodi_list_file_backups` finds existing
    snapshots; `kodi_restore_file` restores one with a current-file checksum check.
- **Manager configuration:** `kodi_create_configuration_backup` makes a configuration checkpoint.
  - Find it with `kodi_inspect_manager(area="backups")`, then use `kodi_restore_configuration`.
  - These IDs are separate from local file snapshots and APK recovery bundles.
- **Manager layout:** inspect the existing layout, stage with `kodi_preview_layout`, review and
  apply its `preview_id` with `kodi_apply_layout`. Rebuilding skin menus is a separate visible action.

## Full Android catalogue

*Write mode* requires the write opt-in. *Device interaction* can show a debugging prompt or run
provider code; *private staging* saves preview/backup state. Read-only tools can still save private
local rollback data where stated. Logs, screenshots and backups may contain private information.

## Check definition quality without a TV

Maintainers can export definitions with synthetic localhost configuration. Exporting only calls
`tools/list`; it does not probe a device or load the user's environment/configuration.

```sh
python scripts/export_tool_catalog.py --output /tmp/nvidia-tools.json
npx --yes mcp-tdqs@0.2.0 lint --file /tmp/nvidia-tools.json
```

Use `--profile full --writes --manager --plugin-browse` on the exporter to review all Android
features. Lint checks schemas and flags possible overlap; it is not a model score. Full-profile
shadow warnings need human review: restoring saved file bytes cannot choose a new setting value,
preview/apply text replacements or stage Manager layout rows. Screenshot responses are PNG image
content rather than structured JSON, as their description states.

The parameter-coverage and protocol checks run in CI. Glama's published score comes from its own
indexed tool snapshot; pushing a commit does not certify a new score. The listing's owner can
request a repository re-sync in Glama's Admin page after signing in with GitHub.
